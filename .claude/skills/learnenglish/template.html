Building an LLM Gateway from Scratch

Core idea
  • Build a gateway only when configuration cannot do what you need, such as an exact budget cap.
  • Clients ask for a purpose (fast, smart). The alias maps to an ordered chain that ends with a local model.
  • Fall back only on transient errors: timeouts, 5xx and 429. A 400 means the request itself is wrong.
Try it

Input 1000 tokens, max_tokens 500, prices $0.20 and $0.60 per million. The answer uses 120 output tokens. How much is reserved, and how much is refunded?

reserve = 1000*0.20 + 500*0.60      # = 500 micro-USD, worst case
actual  = 1000*0.20 + 120*0.60      # = 272 micro-USD, real usage
refund  = reserve - actual          # = 228 micro-USD back to the budget
# keep money as integers (micro-USD): floats drift after millions of calls

Retry only transient failures, such as timeouts.

Quick check
Why must the last link of every chain be a local model?

It keeps the service answering when every cloud provider is down or the quota is gone.

Why reserve first and settle after, instead of checking the balance?

The check and the update happen in one atomic step, so two concurrent requests cannot both pass.
