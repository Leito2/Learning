Note 00 · Applied in P1 milestone M7c

Welcome to gRPC for ML Services

Core idea
  • gRPC is typed calls between services: a contract in a .proto file, generated stubs, and binary messages over HTTP/2.
  • Use it for service-to-service calls with a latency budget. Keep REST for public and demo APIs, and SSE for streams to a browser.
  • A deadline travels with the call, so a slow service can stop work the caller has already given up on.
Try it

A checkout allows 50 ms in total. The call spent 12 ms on the network and 18 ms on feature lookup. The model needs 25 ms. What should the server do?

budget_ms = 50
left = budget_ms - 12 - 18     # 20 ms left for the model
# the model needs 25 ms > 20 ms: the caller will give up first,
# so answer early (fallback or DEADLINE_EXCEEDED) instead of working for nothing

Client and server must line up on the same contract.

Quick check
When would you choose SSE instead of gRPC?

When a server pushes tokens to a browser. SSE is a one-way stream over plain HTTP, and browsers support it directly.

What is a deadline, and who sets it?

The moment after which the caller no longer wants the answer. The client sets it, and it travels with the call so the server can see it.

Note 01 · Applied in P1 milestone M7c

Protocol Buffers and Contract-First APIs

Core idea
  • The .proto file is the API. Client and server code are generated from it, so they cannot drift apart.
  • The wire carries field numbers, not names. Never change or reuse a number, and write reserved when you remove a field.
  • Enum zero is UNSPECIFIED. Use optional when "not sent" must differ from the default. buf breaking in CI checks compatibility.
Try it

Which of these changes break old clients?

# a) add field 14             -> safe (old readers ignore it)
# b) rename amount to total   -> binary safe, JSON and generated code break
# c) double amount -> string  -> BREAKS (the wire type changes)
# d) reuse removed number 3   -> BREAKS (old data lands in the new field)
Words from this note

Slowly become different from each other.
Without a shared contract, client and server drift apart.

roll outphrasal verb

Release something step by step.
Roll out the new field first, then update the clients.

single source of truthphrase

One place that holds the correct information.
The .proto file is the single source of truth for the API.

backward compatiblecollocation

Works with older versions of the software.
Adding a field with a new number is backward compatible.

A change that makes existing clients fail.

by conventionphrase

Because most people usually do it this way.
By convention, the first enum value is UNSPECIFIED.

Quick check
Why can you rename a field but not renumber it?

The wire carries the number, not the name. Old binary clients still decode the field by its number.

What does reserved 3; do?

It stops anyone from using number 3 in this message again, so old data cannot land in a new field.

Note 02 · Applied in P1 milestone M7c

Async gRPC Servers and Clients in Python

Core idea
  • There are four call types: unary and three kinds of streaming. Bidirectional streams keep one call open for many messages.
  • Never run the model directly on the event loop. Use asyncio.to_thread, and create the channel once per process.
  • A micro-batch sends N messages or waits T ms, whichever comes first. A bigger T gives more throughput and more delay.
Try it

Messages arrive every 1 ms, starting at 0. The limits are N = 8 and T = 5 ms. When is the batch sent, and how many items does it hold?

# t = 0, 1, 2, 3, 4 ms -> 5 items, still below N = 8
# at t = 5 ms the time limit hits: send the batch now
# the first item waited 5 ms, the last one about 1 ms
Words from this note
tie upphrasal verb

Keep busy so that others cannot use it.
A blocking model call ties up the event loop.

spin upphrasal verb

Start something new, often quickly.
Do not spin up a new channel for every request.

hot pathcompound noun

The code that runs on every request.
Creating connections on the hot path slows every call.

throughputnoun

The amount of work done in a period of time.
Micro-batching raises throughput but adds a small delay.

Report an error at once instead of waiting.
The server fails fast when it is already full.

whichever comes firstsentence frame

Use the one that happens earlier.
Send the batch after 8 items or 5 ms, whichever comes first.

Quick check
Why must model inference not run directly inside an async handler?

It blocks the event loop, so no other call is served and every pending deadline gets closer. Use asyncio.to_thread or a process pool.

Why create the channel once?

A channel is a long-lived HTTP/2 connection that carries many calls. A new channel per request pays the connection setup every time.

Note 03 · Applied in P1 milestone M7c

Deadlines, Retries and Error Handling

Core idea
  • Set a deadline on every call. The default is no deadline, so a forgotten one waits forever.
  • The server reads context.time_remaining() and answers with fallback features when time is short. Python does not forward deadlines for you.
  • Retry only UNAVAILABLE on idempotent calls, inside the same deadline. Return typed errors with context.abort.
Try it

The deadline is 50 ms. Attempt 1 fails with UNAVAILABLE after 20 ms. The backoff is 10 ms and a second attempt needs 25 ms. Does it fit?

left = 50 - 20 - 10        # 20 ms left after the failure and the backoff
fits = left >= 25          # False: the retry cannot finish
# answer with fallback features (degraded) instead of retrying
Words from this note

Stop something before it finishes.
A deadline cuts off a call that takes too long.

bail outphrasal verb

Leave a situation early to avoid a problem.
The server bails out early when no time is left.

Giving a reduced service instead of failing completely.
Fallback features are a form of graceful degradation.

idempotentadjective

Safe to repeat: the result is the same.
Only retry calls that are idempotent.

Many retries together that overload a service.
Backoff and limits prevent a retry storm.

In addition to something that already exists.
Retries add load on top of the normal traffic.

Quick check
What is the difference between a timeout and a deadline?

A timeout is a duration from now. A deadline is a fixed moment that travels with the call, so every hop knows how much time is left.

Why must retried calls be idempotent?

The first attempt may have reached the server before the connection failed. A repeat must not apply the same action twice.

Note 04 · Applied in P1 milestone M7c

Production gRPC: Interceptors, Health and Observability

Core idea
  • Interceptors wrap every call for auth, metrics and traces. Put auth first. Metric labels stay small: method and status code.
  • The health service reports SERVING only after the model loads, and NOT_SERVING before shutdown. Reflection plus grpcurl lets you debug without the .proto.
  • A layer-4 balancer picks a server once per connection, so one long gRPC channel sticks to one server. Use a layer-7 proxy or client-side balancing.
Try it

A client opens one channel through a layer-4 balancer to 4 servers and sends 1,000 calls. How many servers receive traffic? What changes with a layer-7 proxy?

# L4: the server is chosen once, when the connection opens
servers_used = 1            # all 1,000 calls go to the same server
# L7 proxy or client-side round_robin: each call is balanced
servers_used = 4            # about 250 calls per server
Words from this note

Attach to one fixed place.
A layer-4 balancer pins a channel to one server.

Track the golden signals for every method.

Quick check
Why report NOT_SERVING before the service stops?

The balancer or orchestrator stops sending new calls, and the running calls can finish during the grace period.

Why avoid a user_id label in metrics?

Each value creates a new time series. Millions of series overload the metrics system.

Note 05 · Applied in P1 experiment E11

Benchmarking REST vs gRPC

Core idea
  • A protocol only speeds up what it controls: connections and serialization. If the model dominates the time, the gain is small. That is an honest result.
  • Use open-loop load (a fixed arrival rate). Closed-loop tests slow down with the server and hide the delay (coordinated omission).
  • Hold everything else constant, warm up, repeat 3 or more times, and use a confidence interval before you claim a difference.
Try it

Inference takes 20 ms. REST overhead is 4 ms and gRPC overhead is 1.5 ms. What is the best-case gain of gRPC?

rest, grpc = 20 + 4, 20 + 1.5      # 24 ms vs 21.5 ms
gain = (rest - grpc) / rest        # 0.104 -> about 10% at best
# if inference were 90% of the time, the gain would be even smaller

Quick check
Why use an open-loop test for latency?

Requests arrive at a fixed rate even when the server is slow, so queueing shows up in the latency. A closed-loop test slows down with the server and hides the problem.

What is capacity at SLO?

The highest request rate at which the p99 latency stays under the agreed budget.

Note 06 · Bridge to P1 milestone M7c

Bridge to Project: Synchronous Scoring in P1

Core idea
  • P1 keeps the Kafka path and adds gRPC for checkout: Score (50 ms deadline), ScoreStream (micro-batches) and GetDecision (for P2).
  • The gRPC server is a second entrypoint that shares the same scoring use case, so both paths score the same way.
  • M7c is done when grpcurl calls all 3 methods, an expired deadline returns DEADLINE_EXCEEDED in a test, and experiment E11 is published.
Try it

Write the test that proves the deadline rule. What status code must the client receive?

with pytest.raises(grpc.aio.AioRpcError) as err:
    await stub.Score(payment, timeout=0.0001)    # no server answers in 0.1 ms
assert err.value.code() == grpc.StatusCode.DEADLINE_EXCEEDED

What must happen when Redis is too slow for the deadline?

The server uses fallback features and returns degraded = true inside the deadline, instead of failing with DEADLINE_EXCEEDED.

When is "parity" the right conclusion of E11?

When the p99 difference between REST and gRPC is inside the confidence interval, usually because inference dominates latency.
